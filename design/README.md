  --bg-deepest:   #050606;  /* 最深底（carbon black 1000） */

## 二、四条规则

**1. 深色分层靠明度差，不靠阴影。**
`#0A0C0C` → `#131515` → `#1C1E1E`，每级只差 2~4%。深色底上打投影会糊成一团。

**2. 灰阶必须是中性的，色相偏一点都会毁掉黄色。**
这是花了两次才搞明白的一条。终末地的碳黑阶是 **R 略低于 G=B**（`#0A0C0C` = 10,12,12）——冷中性。
如果误用**绿调灰**（比如 `#2E3331` = 46,51,49，G 最高、色相 156°；或 `#EDF0EA` 这种黄绿白），那**整屏的灰会先把画面带成橄榄色**，这时候无论黄色多正，看起来都是芥末/屎黄。
> 自检方法：把设计稿截图，统计"暗部像素的均值"。**`G−R` 和 `B−R` 都应该是 +2 左右，`G` 与 `B` 相等**；如果 `G` 明显高于 `R`，就是绿了。

**3. 结构线用实色暖/冷中性灰，不用 `rgba(255,255,255,0.09)`。**
通用白色低透明在有色相的底上会发脏。统一 `1px solid #2C3030`。

**4. 全直角。**
所有 `border-radius: 0`。直角体系里没有"圆角"这个层级手段，层级只能靠 ① 背景明度差 ② 发丝线 ③ 字号字重。

### 四条无障碍规则（不能省）
焦点环永久可见（`outline: 2px solid var(--accent)`，永不移除）；响应 `prefers-reduced-motion`；颜色不得为唯一信息手段；正文 ≥4.5:1。

## 二之二、⚠️ 黄色配额表（本次最重要的一节）

**结论先讲**：终末地的黄是 **警戒色（caution yellow）**，语义是"在机器上划一道线"，**不是油漆**。官方原话——「只要涉及**大面积用色**，色彩通常偏暗或偏淡，向**黑白两极**靠拢……而在 UI 和场景建筑上，能看到标志性的**明黄警戒色**」。评测里也写「**黑白灰打底**，**点缀**着柠檬黄」。

所以黄的使用有硬配额：

| 规则 | 内容 |
|---|---|
| **R1 面积** | 任何**单个实心黄填充块 ≤ 28×28px**；全屏黄色像素占比 **≤1%** |
| **R2 按钮** | **所有按钮一律"碳黑底 + 1px 黄描边 + 黄字黄图标"，不用黄底。** 不论主次、不论大小 |
| **R3 线状** | 宽或高 **≤4px** 的线状元素可以是实心黄（未读条、电量/进度填充、代码块左导轨、焦点环） |
| **R4 文字** | 黄字只用于 **≤13px** 的标签 / 链接 / 状态词；**≥20px 的大数字一律用 `--text-1`** |
| **R5 描边** | 图标描边、卡片/按钮 1px 边可以是黄 |
| **R6 徽章** | 计数**只做黄字，不做黄底填充** |
| **R7 语义** | 黄只表达**状态/焦点/当前项**；不要用它区分"分类"（分类点改用中性灰） |

**每屏允许出现的黄（白名单）**

| 位置 | 形态 | 实测 |
|---|---|---|
| 品牌 Logo 块 | 实心，28×28 / 26×26 | ✅ R1 |
| 状态点（ONLINE） | 实心，6×6 | ✅ R1 |
| 小节标记块 | 实心，8×8 | ✅ R1 |
| 复选框（勾选态） | 实心，14×14 | ✅ R1 |
| 未读左色条 | 线，3px 宽 | ✅ R3 |
| 电量/存储条填充 | 线，3px 高 | ✅ R3 |
| 当前导航项图标 | 描边 | ✅ R5 |
| 当前 Tab 图标 + 标签 | 描边 + 11px 字 | ✅ R4/R5 |
| 链接 / 小节标签 / 单位 | ≤13px 字 | ✅ R4 |
| 主按钮 | 1px 边框 + 13px 字 + 16px 图标 | ✅ R2 |
| 输入框焦点环 | 1px 边框 | ✅ R5 |

**禁止清单**：黄底大按钮、黄底大数字（≥20px）、黄底徽章、黄底卡片、黄底栏位、用黄区分分类。

> **实测结果**：登录桌面 **0.31%**、收件桌面 **0.19%**、登录手机 **1.01%**（几乎全是小字号文字）、收件手机 **0.27%**。
> 改前"黄铺底"版本的大按钮单块就有 ~17,000px²（占桌面屏面 1.3%），现在**最大的单块黄只有 28×28 = 784px²**。

## 二之三、8pt 网格（间距）

字号不必对齐 8，但**字号周围的间距必须**：

```
4px   图标与文字之间（半分步）      24px  元素组之间
8px   紧密相关元素                 32px  区块之间
12px                              48px
16px  组件内部 padding             64px  大区块分离
```

字号底线：手机端底部 Tab 标签原为 9px（低于 iOS 11pt 下限），已提到 **11px**。

## 三、字体怎么分

| 用途 | 字体 | 字重与设置 |
|---|---|---|
| 中文标题（页面主标题、阅读区标题） | Source Han Sans CN | **Heavy**，负字距 `-0.5px` |
| 中文正文 | Source Han Sans CN | Regular（次级标题用 Medium / Bold） |
| 拉丁大标题（品牌字、统计数字） | Saira Condensed | Bold / Black，大写 |
| 数据、编号、时间戳、邮箱、密钥 | Saira Condensed | Regular / Medium |

> ⚠️ 终末地**不用等宽字体**。"技术感"来自 Saira 的**窄体（condensed）轴** + 大写 + 紧排，比 JetBrains Mono 更贴身、更像仪器面板上的丝印字。所以本稿把 `--font-mono` 整个换成了 `Saira Condensed`。

## 四、桌面 → 手机 的对应关系

| | 桌面 | 手机 |
|---|---|---|
| 登录页 | 左品牌区 + 右登录卡（880 / 560 分栏） | 单列；品牌区压缩成顶部一行 |
| 收件箱 | 三栏：侧栏 248 + 列表 384 + 阅读 808 | 单列邮件列表 + 底部 Tab 栏 |
| 顶栏 | 搜索框 + 「写邮件」文字按钮 | 标题 + 图标按钮 |
| 状态栏 | 底部一行服务状态（IMAP/SMTP/TLS） | 顶部系统状态栏（时间/信号/电池） |
| 背景 | 无网格 | 带 `#2C3030` 工程网格（50% 不透明） |

窄屏不是把桌面缩小，而是**换一套信息结构**：三栏变单列、阅读区拆成独立页面、导航从侧栏移到底部。
